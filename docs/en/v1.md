# Migrating from v1

> The next major release introduces breaking changes. This guide walks through each one with a Before/After diff so you can migrate a v1 codebase in a single pass.

If you are starting fresh, skip this page and go to [Getting Started](./guide/getting-started.md) instead.

## Overview

The v1 to v2 rewrite refactors `OhNetBuilder` into `OhNetClient` and consolidates state ownership. The library is now strictly immutable: each configuration call returns a fresh instance, every field on the client is `readonly`, and the dispatcher mutates a caller-provided context instead of touching the client.

Four surfaces changed:

1. **Class and constructor** - `OhNetBuilder` to `OhNetClient`; `new ...(config)` to `OhNetClient.create(config)`
2. **`fork` signature** - accepts a 4-field options object instead of an `OhNetConfig`
3. **Middleware and event queries** - `get middleware()` / `get event()` getters replaced by `middlewares()` / `events()` methods
4. **Type names** - `OhNetMiddlewareBuilder` / `OhNetEventBuilder` removed; replaced by `OhNetMiddlewareQuery` / `OhNetEventQuery`

Everything else (`with` / `clean` / `on` / `off` / `append` / HTTP verbs / `request`) keeps the same signature and behavior.

## Quick Checklist

Run through this list first; each item links to the detailed section below.

- [ ] Replace `import { OhNetBuilder }` with `import { OhNetClient }`
- [ ] Replace every `new OhNetBuilder(config)` with `OhNetClient.create(config)`
- [ ] Replace `client.middleware.list()` / `.has()` / `.get()` with `client.middlewares().list()` / `.has()` / `.get()`
- [ ] Replace `client.event.list(event?)` with `client.events().list(event?)`
- [ ] If you imported `OhNetMiddlewareBuilder` / `OhNetEventBuilder` types, switch to `OhNetMiddlewareQuery` / `OhNetEventQuery` (note: no longer exported from the public entry)
- [ ] Update `@see` links in your jsdoc that pointed to `reference/builder.html` - the URL moved to `reference/client.html`

## Class & Constructor

The public class renamed and the constructor is now private. Construction goes through a static factory.

**Before (v1)**

```ts
import { OhNetBuilder } from "@xtwis/ohnet"

const client = new OhNetBuilder({
  url: "https://api.example.com",
  adapter: myAdapter,
  headers: { "x-app": "demo" },
})
```

**After (v2)**

```ts
import { OhNetClient } from "@xtwis/ohnet"

const client = OhNetClient.create({
  url: "https://api.example.com",
  adapter: myAdapter,
  headers: { "x-app": "demo" },
})
```

`OhNetConfig` is unchanged; only the call shape differs.

## `fork` Signature

`fork` no longer takes an `OhNetConfig`. It takes an options object with four optional fields; each omitted field is inherited from the receiver.

**Before (v1)**

```ts
const v2 = client.fork({ url: "/v2", headers: { "x-version": "2" } })
```

**After (v2)** - replace middleware / event / adapter / context via the options object:

```ts
// Replace the middleware list outright
const stripped = client.fork({ middlewares: [] })

// Replace the event registry outright
const quiet = client.fork({ events: new Map() })

// Swap the transport
const grpc = client.fork({ adapter: grpcAdapter })
```

For request-shaped fields like `url`, `headers`, or `params`, use `add(config)` instead of `fork`.

`fork` defaults copy the receiver's `middlewares` and `events` by value, so even an empty `fork()` call produces a new instance you can mutate independently.

## Middleware and Event Queries

The single getters became methods. The returned type changed from `OhNetMiddlewareBuilder` / `OhNetEventBuilder` to the read-only `OhNetMiddlewareQuery` / `OhNetEventQuery`.

**Before (v1)**

```ts
client.middleware.list() // => OhNetMiddleware[]
client.middleware.has("auth") // => boolean
client.middleware.get("auth") // => OhNetMiddleware | undefined

client.event.list("on_start") // => readonly OhNetEventHandler[]
client.event.list() // => readonly OhNetEventHandler[] (all events)
```

**After (v2)**

```ts
client.middlewares().list() // => readonly OhNetMiddleware[]
client.middlewares().has("auth") // => boolean
client.middlewares().get("auth") // => OhNetMiddleware | undefined

client.events().list("on_start") // => readonly OhNetEventHandler[]
client.events().list() // => readonly OhNetEventHandler[] (all events)
```

Each call returns a fresh snapshot; mutations on the query never propagate back to the client.

`OhNetEventQuery.get(event)` is **new** - it returns `readonly OhNetEventHandler[] | undefined`, where `undefined` means no handler is registered. (In v1, the event registry did not expose `get`.)

## Type Renames

| v1                       | v2                     |
| ------------------------ | ---------------------- |
| `OhNetBuilder`           | `OhNetClient`          |
| `OhNetMiddlewareBuilder` | `OhNetMiddlewareQuery` |
| `OhNetEventBuilder`      | `OhNetEventQuery`      |

`OhNetMiddlewareQuery` and `OhNetEventQuery` are **internal** types in v2 - they are not re-exported from the public entry. If your code references them, narrow to the inline shape returned by `middlewares()` / `events()` (a structural type with `get` / `has` / `list`) instead of importing the named class.

```ts
// v1
//   import { OhNetBuilder, OhNetMiddlewareBuilder } from "@xtwis/ohnet"
//   const b: OhNetMiddlewareBuilder = client.middleware

// v2
//   import { OhNetClient } from "@xtwis/ohnet"
const q = client.middlewares() // structural type, no name import needed
const list = q.list() // readonly OhNetMiddleware[]
```

## What Did NOT Change

These APIs are byte-identical between v1 and v2:

- `with(middleware)` and `clean(name)` - same name, same replacement semantics, same `OHNET_MIDDLEWARE_NAME` throw
- `on(event, callback)` and `off(event, target)` - same registration order, same identity-based removal
- `append(path)` - same URL concatenation, same lack of separator insertion
- All HTTP verbs (`get` / `post` / `put` / `delete` / `patch` / `head` / `options`) - same signature, same parameter shape
- `request<T>(config?)` - same per-request overrides contract; the user-facing behavior is unchanged
- `OhNetMiddleware`, `OhNetEventHandler`, `OHNET_EVENT`, `OHNET_ERROR_CODE` constants and types - unchanged

If your v1 code uses only these, no edits are required after the import rename.
